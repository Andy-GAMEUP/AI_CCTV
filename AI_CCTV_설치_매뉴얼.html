02

CCTV 위치를 정하고 설치하세요

천장에 고정하기 전, 짧은 케이블로 먼저 영상이 나오는지 확인하면 재작업을 줄일 수 있습니다.

배치 예시

카메라 01 · 출입구

출입 동선이 가려지지 않는 위치. 유리문·외부 햇빛이 정면으로 들어와 사람이 어둡게 보이지 않는지 확인합니다.

배치 예시

카메라 02·03 · 매장 / 계산대

02는 주요 통로·관심 구역, 03은 계산대 뒤쪽 측면 또는 정후방에서 거래 영역을 비추도록 배치합니다.

  1. 촬영 범위와 케이블 경로를 표시합니다.

    카메라에 CAM-01, CAM-02, CAM-03 이름을 붙입니다. 선 양끝에도 같은 라벨을 붙입니다. 실제 영상으로 사각지대를 확인하세요.

  2. 권장 높이와 시야를 확인합니다.

    원본 예시 카메라의 권장 높이는 2.5~3.5m입니다. 천장이 높으면 적합한 연장 브래킷을 사용합니다. 조명·기둥·간판·선반이 시야를 가리지 않게 합니다.

  3. 브래킷과 본체를 단단히 고정합니다.

    고정 작업 전 카메라 전원을 분리하고, 천장·벽 재질에 맞는 피스와 앙카를 사용합니다. 높은 곳의 작업은 안전한 작업대와 보조 인원을 확보해 진행합니다.

  4. UTP를 카메라에서 스위치 위치까지 배선합니다.

    커넥터에 하중이 걸리지 않게 여유를 두고, 꼬리 케이블·단자는 천장 또는 브래킷 단자함 안에 정리합니다. 집선부 고정 간격은 원본 기준 15cm 이하이며, 타이를 과하게 조이지 않습니다.

높이·감지 범위는 카메라 모델별로 확인원본 예시 DX-1002H2N(P/QS)은 3.6mm 렌즈, 거리 8m, 각도 67°, 안면인식 유효거리 5m, 커버면적 37㎡로 표기되어 있습니다. 다른 돔형 카메라에 동일 수치를 적용하지 마세요.

03

셋탑과 내장 HDD를 준비하세요

이미 HDD가 장착되어 있으면 규격·장착 상태 확인 후 다음 단계로 진행합니다.

케이스를 열기 전에는 반드시 전원 어댑터를 빼세요원본은 무전원 상태에서 HDD 장착을 지시합니다. 분해·장착을 지원하지 않는 납품 조건이면 공급업체에 장착을 요청하세요.
  1. 본체를 평평한 곳에 놓고 케이스를 엽니다.

    원본 예시는 전면 양측 나사를 풀고 상판을 뒤쪽으로 밀어 분리합니다. 실제 케이스 구조가 다르면 해당 모델 안내를 따릅니다.

  2. HDD를 4개 나사로 고정합니다.

    HDD의 장착 구멍 4개를 본체 구멍에 맞춘 뒤 고정합니다. 내부 케이블을 끼우거나 누르지 않게 합니다.

  3. HDD 데이터 케이블과 전원 케이블을 연결합니다.

    지원 규격에 맞는 데이터·전원 커넥터를 HDD와 메인보드에 연결합니다. 방향을 맞춰 꽂고 힘으로 밀어 넣지 않습니다.

  4. 뚜껑을 닫고 통풍이 되는 곳에 둡니다.

    나사를 조이고, 단단하고 수평인 바닥이나 랙 트레이에 설치합니다. 위에 다른 장비를 쌓지 말고 통풍구를 비워 둡니다. 전원은 배선 점검 후 연결합니다.

04

공유기 → 스위치 → 장치를 연결하세요

모든 카메라·셋탑·노트북이 같은 내부 네트워크에 있도록 구성합니다.

초록선 = 호환 PoE 전원 + 데이터 / 파란선 = 데이터. 전원 배선은 생략했습니다. PoE 분리기가 필요한 카메라는 중간에 분리기를 연결합니다.

  1. 인터넷 선을 공유기 WAN / Internet 포트에 연결합니다.

    공유기 전원을 켜고 노트북으로 인터넷 접속부터 확인합니다. 인터넷 회선 인증이나 고정 IP가 필요한 현장은 회선 담당자의 설정값을 사용합니다.

  2. 공유기의 내부망과 DHCP를 확인합니다.

    DHCP는 장치에 IP 주소를 자동 배정하는 기능입니다. 공유기 관리 화면에서 LAN 주소, 서브넷 마스크, DHCP 사용 여부와 배정 범위를 기록합니다. 공유기 주소·관리 비밀번호는 해당 제품 라벨/매뉴얼을 확인합니다.

  3. 공유기 LAN → 스위치 일반 Uplink/LAN을 연결합니다.

    WAN과 LAN을 혼동하지 마세요. 스위치 전원을 연결하고, 격리·VLAN 모드가 있다면 이 설치용 내부망의 장치끼리 통신하도록 구성합니다. PoE 전용 NVR 내부 포트는 이 공통망과 다를 수 있으므로 임의로 대체하지 않습니다.

  4. 카메라 3대 → 호환 PoE 포트에 연결합니다.

    각 포트와 케이블 라벨을 맞춥니다. 일부 모델은 PoE 분리기의 데이터·DC 출력을 카메라에 각각 연결해야 합니다. 규격 미확인 패시브 PoE를 사용하지 마세요.

  5. 스위치 일반 데이터 포트 → 셋탑 LAN에 연결합니다.

    셋탑은 원본 기준 기본 제공 DC 전원 어댑터로 별도 전원을 공급합니다. 공유기·노트북·셋탑에는 일반 업링크/데이터 포트 또는 비PoE 장치 호환이 확인된 포트를 사용합니다.

  6. 전원과 링크 표시등을 확인합니다.

    셋탑을 켜고 부팅을 기다립니다. 공유기·스위치·카메라·셋탑 케이블을 가볍게 확인해 빠짐이 없는지 보고 포트의 Link/Act 표시등이 켜지는지 확인합니다.

공유기에 셋탑을 직접 꽂아도 되나요?같은 내부 LAN에 연결되면 가능합니다. 이 가이드는 원본처럼 스위치에 모으는 구성을 사용합니다. 셋탑은 스위치의 일반 데이터 포트, 카메라는 전원 호환이 확인된 PoE 포트에 연결하는 것이 구분하기 쉽습니다.

근거: 두 원본 PDF 3쪽의 구성도, 카메라 PDF 6쪽 및 저장장비 PDF 5~6쪽. 포트 배치·공유기 점검은 초보자용 보충 안내입니다.

05

노트북을 같은 네트워크에 연결하세요

노트북과 셋탑은 같은 스위치를 통해 통신합니다.

  1. 노트북 LAN → 스위치 일반 데이터 포트에 연결합니다.

    LAN 포트가 없으면 USB-LAN 어댑터를 사용합니다. 공유기 LAN에 연결해도 같은 내부망이면 가능합니다. 최초 설정은 유선 연결을 권장합니다.

  2. 노트북의 IPv4 주소를 자동으로 받도록 설정합니다.

    Windows: 설정 → 네트워크 및 인터넷 → 이더넷 → IP 할당 편집 → 자동(DHCP). macOS: 시스템 설정 → 네트워크 → 사용 중인 이더넷 → 세부사항 → TCP/IP → IPv4 구성 → DHCP 사용. OS 버전에 따라 메뉴 이름은 다를 수 있습니다.

  3. 노트북 IP와 기본 게이트웨이를 기록합니다.

  4. 공급업체에서 받은 구성 도구를 실행합니다.

    원본 명칭은 「클라우드 감시 구성 도구」이며 화면에는 YUNDVISION이 보입니다. 공급업체가 제공한 지원 OS와 버전을 사용하세요. macOS에서 실행 가능하다는 정보는 원본에 없으므로, 지원되지 않으면 호환되는 Windows 노트북을 준비합니다.

  5. 새로고침 / 장치 검색을 누릅니다.

    카메라 3대와 셋탑을 모델·시리얼번호·MAC 주소로 대조합니다. IP만 보고 임의의 장치를 설정하지 마세요. 검색이 안 되면 VPN·다른 Wi-Fi 경로·게스트망·스위치 격리를 확인합니다.

분석 기능과 실제 녹화를 확인하세요

영상이 보이는 것과 방문객 분석 데이터가 수집되는 것은 각각 확인해야 합니다.

  1. 지원 카메라의 핫존·동선 분석을 켭니다.구성 도구 → 핫스팟(열점) / 고객 동선 → 대상 장치 → 핫스팟

    활성화 체크 여부와 모니터링 시간을 확인하고 저장합니다. 원본 예시 카메라에 대한 경로이므로, 다른 모델에 메뉴가 없으면 분석 지원 여부를 확인하세요.

  2. 영업시간과 장치 시간을 대조합니다.

    모니터링 시간이 실제 영업시간을 포함하는지, 장치 표시 시간과 현장 시간이 맞는지 확인합니다. 시간·시간대 변경 메뉴는 해당 펌웨어 설명을 따릅니다.

  3. 같은 사람이 각 구역을 이동하며 시험합니다.

    출입구→매장→계산대로 이동해 사람이 가려지지 않는지, 영상이 끊기지 않는지 확인합니다. 지원되는 분석 화면에서 데이터가 실제 반영되는지 확인합니다. 이 절차만으로 방문객 수의 정확도나 중복 제거 성능을 보증하지는 않습니다.

  4. 녹화한 구간을 다시 재생합니다.

    카메라 3대 모두 현재 영상뿐 아니라 조금 전 녹화 구간도 재생합니다. 재생되지 않으면 HDD 상태, 채널 녹화 활성화, 녹화 시간표를 확인하고 해당 모델 설정 안내를 받습니다.

  5. 클라우드를 사용할 경우 플랫폼 등록을 완료합니다.

    카메라 원본은 ‘클라우드 감시 360’ 플랫폼에 로그인 후 워크벤치 → 시스템 설정 → 시스템 관리에서 매장/지역을 만드는 시작 단계까지만 제공합니다. 현재 콘솔 URL·등록 양식·조회 메뉴를 직접 확인한 내용은 10~16단계를 참고하세요. 실제 장치 바인딩과 분석 결과는 공급업체 테스트 환경에서 검수해야 합니다.

매장·장치를 콘솔에 등록하는 방법

확인된 양식과 미검증 후속 단계를 표시했습니다.

최초 등록 · 매장 → 장치 → 구역 → 연결·분석 확인

실제 입력 양식을 확인했지만 저장 이후 단계는 미검증입니다. 납품 정보와 권한을 확인한 후 담당자가 등록하세요. 공식 설명으로 보완된 절차는 14단계, API 준비는 15단계에 정리했습니다.

  1. 매장과 영업시간을 만듭니다.Workbench → System configuration → System management → Stores architecture → Add a store

    전체 메뉴 화면에서는 상단 System Management로 이동합니다. 생성 양식 단계: Create a store → Associated device → Create in-store zone.

    필수 표시: Belonging region, Store name, Store number, Address, Detailed address, Business status, Launch time, Store area(m²). 영업시간은 Repeat every day / Repeat every week로 나뉩니다. 확인 시 양식 기본 시간 10:00~22:00는 실제 영업시간으로 수정해야 합니다. 한국 주소 지도와 시간대는 공급사 확인 대상입니다.

    Save&Next / Skip the next steps and save directly 버튼을 확인했습니다. 저장 후 장치·구역 연결 화면은 공급사 매뉴얼과 대조하세요.

  2. 모델별 등록 유형과 key를 확인합니다.Device management → Device Config → Add device

    필수 표시: Serial number, Device name, Device type, Associated store. 추가 항목: key, Associated in-store zone, Inherit store access rights(확인 시 체크됨). key는 필수 표시가 없지만 모델별 필요 여부·발급 위치는 미확인입니다. 매장 선택 전 구역은 비활성 상태였습니다.

    유형: Video device / Traffic(in) device / Traffic(pass) device / Storage device / Attention device / Traffic(in&pass) device. DX-1100 유형 및 카메라 별도 등록 여부는 공급사에서 확정받으세요. 명칭만 보고 Storage device를 임의 선택하지 않습니다. 기존 바인딩을 확인하고, 매장 접근자가 장치 권한도 상속할지 선택한 후 Confirm으로 저장하는 절차입니다.

  3. 온라인 상태와 카메라 3개 채널을 확인합니다.Device management → Device Config / Channel Management

    목록 항목: Device model·Device type·Status·Device binding time·Firmware version·Last online time 등. 매장·유형·상태·Visible 필터가 장치를 숨기지 않는지 확인합니다. 등록 후 셋탑과 3대 카메라의 실제 채널 연결 구조·온라인 상태·영상을 검증해야 합니다.

  4. 분석 구역과 카메라를 매핑합니다.

    Create in-store zone 단계와 Associated in-store zone 항목은 확인했습니다. 실제 도면 업로드·축척·층/구역·카메라 매핑 화면은 현재 빈 매장이라 검증 전입니다. 샘플 매장과 단계별 자료를 받으세요.

공식 WEB 매뉴얼로 정리한 사용가이드

이미 설명된 조작법은 재요청하지 않고, 실제 환경에서의 검수만 남깁니다.

공급사 WEB 문서를 반영한 사용 순서공식 WEB 가이드 ↗ · 기존 10~12단계는 실제 로그인 UI 점검, 이 절은 공급사 문서 근거입니다. 중국어 문서와 현재 영문 UI의 메뉴 구조가 달라 기능 목적을 기준으로 찾으세요. 모든 하위 문서를 완역한 것이 아니라 설치·주요 사용 업무에 관련된 11개 본문을 검토했습니다. 문서에 있는 기능도 이번 장치·권한·라이선스에서 실제 지원하는지는 별도 검수합니다.

01 · 매장·장치·분구 준비

  1. System Management → Stores architecture에서 조직·매장을 구성합니다.

    지역 구조 아래 매장을 만들고 기업 내 고유 Store number를 부여합니다. Address는 지도 좌표·날씨·현장 순찰 위치, Detailed address는 층·호수에 해당합니다. 상태는 운영/중지/폐쇄이며 실제 영업시간이 통계 범위의 기준입니다. 한국 지도 입력·자정 넘김·시간대는 공급사 미결 사항입니다.

  2. 내부 분구를 만들고 장치를 연결합니다.

    분구는 장치 구역 관리와 구역별 집계에 사용됩니다. 실제 도면 업로드·축척·다중 카메라 보정은 별도 안내가 필요합니다. Device Config에서 본체/포장 라벨의 SN과 실제 기능에 맞는 유형·매장을 선택합니다. DX-1100 등록 유형과 key 조건은 아직 미확정입니다.

  3. 권한 상속과 목록 필터를 확인합니다.

    Inherit store access rights를 체크하면 해당 매장 접근자가 장치 접근권한도 상속합니다. 해제하면 이 방식의 권한 부여가 되지 않으므로 기존의 별도 권한까지 삭제되는 것으로 해석하지 마세요. 장치 목록은 매장 권한 범위 내 결과이며 이름/SN·유형·온라인·운영상태·Visible 필터를 확인합니다. API의 display=true/false는 가시성을 뜻합니다.

근거: 매장 구조 ↗ · 장치 목록 ↗ · 장치 API ↗. 화면에서 실제 저장·권한 변경은 수행하지 않았습니다.

02 · 실시간 영상 → 녹화 재생 → 필요한 구간 저장

  1. Video surveillance에서 권한이 있는 매장·채널을 선택합니다.

    매장명·조직·즐겨찾기·태그로 찾습니다. Favorite store는 즐겨찾기, Store traffic은 당일 방문객 추이, Stop all은 열린 영상 종료입니다.

  2. 녹화 시각을 정하고 동기/비동기 재생을 선택합니다.

    동기 재생은 현재 선택 창의 재생 시각을 여러 창에 적용합니다. 비동기는 각 창을 독립 제어합니다. 공식 가이드의 배속은 1×~8×, Layout은 1/4/9화면입니다. PTZ는 지원 카메라에서만 사용합니다. Full screen은 ESC로 종료합니다.

  3. 스냅샷 또는 녹화 구간을 저장합니다.

    Capture all은 현재 재생 중인 화면을 캡처하며 우측에서 확인·다운로드할 수 있습니다. 녹화 다운로드는 재생 시작 시각부터 1/5/10/30분 구간을 선택하는 방식입니다. 방문객/POS가 연계되면 타임라인에 사건 시각을 표시할 수 있습니다. 실제 녹화 존재·다운로드 권한·파일 재생은 E05에서 검수합니다.

준비 순서

  1. API 사용 범위와 전용 계정을 확정합니다.

    기업의 API 개통 여부·기능·요금·권한을 확인하고 공급사 발급 account, enterpriseCode, password를 안전한 경로로 받습니다. 콘솔 계정이나 장치 key를 그대로 API 자격정보라고 가정하지 않습니다.

    POST https://yd.yunding360.com/openapi/oauth/token, JSON 필드 account·enterpriseCode·password. HTTPS·UTF-8 JSON을 사용하고 토큰 응답의 수명에 맞춰 캐시합니다. 비밀값은 HTML·브라우저 저장소·Git 저장소에 넣지 않습니다.

  3. 엔드포인트별 버전과 인증 형식을 확인합니다.

    일반 안내는 api-version: v1, 방문객/체류 조회는 v2를 지정합니다. JSON 본문 요청에는 Content-Type: application/json을 설정합니다. 인증 문서는 tokenType+accessToken 결합 및 공백 없는 예시를 제시하므로, 실제 Authorization 공백·접두어 형식은 공급사의 성공 예시로 확정합니다.

  4. 매장·구역·채널 ID를 얻고 읽기 조회부터 검수합니다.

    0 기반 페이지와 content/metadata를 확인해 전체 페이지를 처리합니다. 서비스별 매장 목록의 대상이 다를 수 있습니다. 같은 한국 현장 기간의 WEB·내보내기·API 숫자를 대조한 뒤 운영에 사용합니다.
